# Skill: ตรวจสอบเราเตอร์และอุปกรณ์ในวงแลน (`router_control`)

## เป้าหมาย

ช่วยให้ทีมงานตรวจสอบอุปกรณ์ในวงแลน ตรวจสอบสุขภาพสัญญาณ Wi-Fi ของจอ Target-R / กล่อง Android Box และอ่านสถานะเชิงลึกของเราเตอร์ 4G LTE (โดยเฉพาะ **D-Link DWR-M930**) วิเคราะห์การเชื่อมต่อ ปัญหาหลุดบ่อย และข้อจำกัดด้านเครือข่าย เช่น CGNAT และ Port Forwarding

---

## ใช้เมื่อ

- ผู้ใช้สั่งให้ **"สแกนหาอุปกรณ์ในวงแลน"** หรือ **"ดูว่ามีเครื่องไหนต่ออยู่บ้าง"**
- ผู้ใช้ต้องการดู **รายชื่ออุปกรณ์ที่เกาะเราเตอร์ (Connected Clients / DHCP Table)** พร้อมระดับสัญญาณ Wi-Fi
- ผู้ใช้ถาม **สถานะเราเตอร์ 4G LTE** (สัญญาณ RSRP, ซิม, ผู้ให้บริการ, คลื่น Band, WAN IP)
- ผู้ใช้ถามเรื่อง **การทำ Port Forwarding, การติด CGNAT, หรือวิธีเชื่อมต่อ/ปิงเราเตอร์จากนอกวงแลน**

---

## Tool ที่เกี่ยวข้อง

- **MCP Tool:** `router_control` (ใน `MCP_SERVER/TOOLS/router_control.md`)
- **Action Options:**
  - `action="scan_devices"`: สแกนเร็วจากคอมฯ ไม่ต้องล็อกอินเราเตอร์
  - `action="get_connected_clients"`: ดึงตารางจากเราเตอร์ แยก LAN/Wi-Fi และวัดสัญญาณ
  - `action="get_router_status"`: วิเคราะห์ 4G, ซิม, CGNAT และคำแนะนำ Network

---

## ข้อจำกัดด้านเน็ตเวิร์กที่สำคัญ (ความรู้พื้นฐานสำหรับ Agent)

### 1. ปัญหา CGNAT กับซิม 4G ทั่วไป
- ซิมมือถือ 4G ทั่วไปเกือบ 100% จะได้รับ **Private IP (10.x.x.x หรือ 100.64.x.x–100.127.x.x)** จากผู้ให้บริการมือถือ ซึ่งติด **CGNAT (Carrier-Grade NAT)**
- **ผลกระทบ:** แม้เราเตอร์จะมีเมนู Port Forwarding / Virtual Server แต่จะไม่สามารถเปิดพอร์ตให้เน็ตภายนอกวิ่งตรงเข้ามาได้ และจากภายนอกจะไม่สามารถปิงหาเราเตอร์ได้

### 2. ทางออกที่ดีที่สุดในการปิง/เข้าถึงเราเตอร์จากนอกวงแลน
- **ใช้ Tailscale Subnet Router บนอุปกรณ์ในวงแลน:**
  - ให้อุปกรณ์ที่เป็น Android Box / คอมพิวเตอร์ หรือ Raspberry Pi ในวงแลนเปิด Tailscale แล้วรันคำสั่ง:
    ```bash
    tailscale up --advertise-routes=192.168.0.0/24
    ```
  - คอมพิวเตอร์ทีมงานจากที่บ้านหรือสาขาอื่น จะสามารถปิงหา `192.168.0.1` (เราเตอร์) และเปิดหน้าเว็บคอนฟิกหรือดูสถานะได้โดยตรง เสมือนนั่งอยู่ในวงแลนเดียวกัน 100% ทะลุ CGNAT ได้อย่างสมบูรณ์แบบ
